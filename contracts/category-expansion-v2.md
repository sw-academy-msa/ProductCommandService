# 카테고리 목록 확장

기존 플랫 목록과 API/이벤트 필드는 유지합니다. 대분류와 중분류 표기는 아래 문서의 정리 기준이며 새 계층 API를 추가하지 않습니다.
기존 4개 분류와 상품을 삭제하거나 일괄 재분류하지 않습니다. 기존 대분류도 호환을 위해 활성 상태로 남깁니다.
새 품목은 대분류의 기존 점검 기준 4개를 사용합니다. AI 추천은 판매자 확인이나 운영자 승인을 대신하지 않습니다.
벡터 DB, 임베딩 API, 자동 카테고리 생성, 개별 상품 유사도 추천은 추가하지 않습니다. GA 기반 개인화 알림 흐름도 변경하지 않습니다.

기존 4개 + 추가 251개 = 총 255개입니다. 색상/사이즈/소재는 카테고리로 추가하지 않습니다.

## 연동 범위

판매자 등록 metadata의 기존 categories와 categoryCriteria에서 새 목록을 제공합니다. AI에는 기존 Requested.categories 필드로 전달하며 모델 결과는 기존 허용 코드/점검 코드 검증을 통과해야 합니다.
Product Query는 승인 상품의 category 이름을 기존 이벤트로 받아 표시합니다. 구매자 카테고리 API는 기존처럼 공개 상품에 있는 분류를 반환합니다. 전체 카테고리 트리 API나 상위 분류 하위 검색은 이번 변경에 포함하지 않습니다.
GA 프런트는 Product Query 상세 응답의 category 이름을 item_category에 기록하는 기존 계약을 유지합니다. 기존 GA 기록을 새 분류로 추정 변환하지 않습니다.
카테고리가 세분화돼도 상품별 알림 횟수/발송 간격 제한이 생기는 것은 아닙니다.

새 분류가 늘어 기존 AI 기술 상한을 초과하므로 요청 목록은 최대 512개, 본문은 1 MiB로 제한합니다. 업무 입력 구조나 Kafka 토픽은 유지합니다.
JSON Schema의 큰 점검 코드 enum은 문자열 타입으로 받되, 서버에서 선택한 카테고리의 실제 점검 코드인지 재검증합니다.

기준표 확장도 기존 분석 fingerprint 변경 사유이므로 초안에서 이전 AI 질문을 새로 채택할 때 재분석이 필요할 수 있습니다. 이미 저장한 FAQ와 상품을 자동 수정하지 않습니다.
